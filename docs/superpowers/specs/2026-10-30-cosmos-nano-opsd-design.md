# Cosmos3-Nano OPSD training design

## Intent and authorization
Add nvidia/Cosmos3-Nano as another video backbone, implement and validate its OPSD trainer, and submit a real Slurm training job. The user explicitly delegated settings and execution without questions. Work in the current checkout to use the existing container and local reward assets; leave the untracked container untouched.

## Architecture and alternatives
Use standard multi-step text-to-video without sound, action, image conditioning, quantization, or inference caches. Preserve the official UniPC pipeline trajectory and capture the intermediate query with temporary transformer/scheduler hooks. A copied Euler rollout would change the baseline; a copied whole Cosmos pipeline would duplicate token packing. Both are rejected in favor of native generation plus differentiable replay of the captured transformer inputs.

The query record contains FP32 pre-step latents, sigma, timestep, guided behavior velocity, detached conditional/unconditional forward inputs, scheduler history before the query, and endpoint. Recompute the query with the trainable adapter for y_theta = z_q - sigma_q v_theta. Reuse branch_loss, opa_tr_step_nd, GeoReward, identity/motion/quality gates, and EMA adapter updates. Implement native fixed-suffix continuation by restoring the saved UniPC history, inserting the forced clean prediction as velocity, and replaying the remaining timesteps with frozen behavior weights. Never change behavior weights during a same-query diagnostic.

## Defaults
One single-node worker with two GPUs: policy on cuda:0; VAE, geometry reward and the isolated VideoReward process share cuda:1. Use native full-frame VAE decoding: overlapping tiling retains all tile backward graphs and exceeds the host allocation under saved-tensor offload. Activation offloading and reduced reward resolution bound memory; full-size backward capacity remains a measured integration gate. Device validation follows configured indices, so a three-GPU layout remains configurable if measured memory requires it. BF16 base weights with FP32 latent arithmetic, rank-16 LoRA on diffusion attention projections, learning rate 1e-5, beta=1, four clips per prompt, 35 UniPC steps, guidance=6, flow_shift=10, 17 frames at 480x832, query_sigma=0.278, rho=0.10, two target steps, 50 optimizer updates with periodic evaluation and resumable checkpoints. Start with an actual one-update integration run before the longer run; this is a gate, not a replacement for training support. Settings are configurable and reduced resolution is an initial compute choice rather than a native-quality claim. Use structured deterministic prompts without an external prompt-generation service.

## Environment and assets
Use an isolated Cosmos dependency overlay or environment rather than changing the established Wan/reward container. Pin a verified Diffusers source revision exposing Cosmos3OmniPipeline and compatible Transformers/PEFT versions. Download only needed Nano components to VIDEO_REWARD_CKPT_PATH, with HF_HOME for caches; record model/library revisions. Preserve existing reward dependency constraints or isolate the quality judge if newer Transformers is incompatible. Fail before submitting on missing imports, weights, or invalid geometry.

## Verification and completion
CPU tests with tiny differentiable packed-input models and the real UniPC scheduler must prove native endpoint parity, query replay parity, CFG gradients, exact scheduler-history restoration, baseline continuation parity, forced-target influence, hook cleanup, VAE gradients, and checkpoint/resume behavior. Run the existing video suite and focused Ruff. On GPU, prove a finite nonzero geometry gradient and policy gradient, parameter update, EMA update, saved checkpoint, and native held-out generation. Submit the training job only with validated environment/assets and record its Slurm ID and status. If external access or compute prevents execution, keep the goal active and record the exact evidence.

## Runtime empty-batch policy
Identity filtering may legitimately reject every clip for a prompt. Skip that sampling batch without updating the optimizer or EMA and advance a deterministic prompt/seed cursor, while preserving the configured total of50 successful optimizer updates. Persist the cursor separately from the optimizer counter; old checkpoints initialize it from the completed-update count. If a full pass through the prompt set is rejected consecutively, stop with a clear error instead of looping forever. Do not lower identity/quality/motion thresholds.
